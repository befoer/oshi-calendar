# 推日 · 角色创作日历

> 名字取自「推し（本命角色）的日子」。GitHub 仓库名：`oshi-calendar`。已有的浏览器数据（IndexedDB、本机设置）沿用内部标识 `huiqi-*`，改名不会丢数据。

本地优先的角色生日与创作规划 PWA。内置 17 位示例角色和原始生图 tag，支持在线搜索添加角色并自动获取 Tag（Danbooru，回退 AnimaDex）、角色标星与筛选、头像保存到本机、自定义公历/农历节日、节气、年度选题、创作任务、JSON 备份和 ICS 日历导出。每个角色只有一个简单的 Tag（只含角色标签），所有复制按钮都直接复制它；发色、瞳色等人物特征另存一份，不随复制。

## 启动

需要 Node.js 22.12+（建议 Node.js 24）。

Windows 日常使用双击 `推日.exe` 或 `start.cmd`。它会检查依赖、按需构建并在默认浏览器打开 http://127.0.0.1:4173 ，服务在后台运行；重复双击会打开同一个工作空间。启动链接带有版本标记，会激活新版离线缓存，避免普通刷新仍停留在旧版；进入后移除标记。首次安装依赖需要联网。exe 显示小型启动窗口，不弹命令行；启动失败显示原因并提供日志入口。服务日志位于 `huiqi-server.log`，exe 启动日志位于 `huiqi-launcher.log`。

`推日.exe` 是 Windows 启动器，仍需安装 Node.js，并与项目文件放在一起；可创建桌面快捷方式。它复用相同启动脚本与端口，保留原有工作空间数据，不是单文件独立应用。启动器源码位于 `scripts/windows-launcher.cs`，在 Windows 中用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-launcher.ps1` 重新编译（使用系统 .NET Framework 4.x）。`推日.exe --check` 可静默验证启动流程并返回退出码，不打开浏览器。

### Electron 版（不用装 Node.js）

`npm run electron:build` 在 `release/` 生成两种包：

- `推日-版本-文件夹版.zip`：解压后双击文件夹里的 `推日.exe`，约 1 秒启动（推荐）。
- `推日-版本-便携版.exe`：单个文件，但每次启动要先解压自身，约 15 秒。

Electron 版在自带窗口里运行，本机资料服务在同一进程内启动，仍使用 http://127.0.0.1:4173 （次元属性联动依赖这个地址）。数据保存在 exe 旁边的 `推日数据` 文件夹，拷走整个文件夹即可带走；它和浏览器版的数据互不相通，可用「设置 → 数据与备份」导出 JSON 后导入迁移。主进程源码在 `electron/main.mjs`，打包时用 `scripts/bundle-electron.mjs` 把它和服务端依赖打成一个文件，所以包里不带 `node_modules`。开发调试用 `npm run electron:dev`（数据放在项目里的 `.electron-data`）。

**发布新版与在线更新**：改好后把 `package.json` 的 `version` 调高（如 1.0.1），提交后打标签推送：

```sh
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions（`.github/workflows/release.yml`）会核对标签与版本号、跑单元测试、打包，并把文件夹版 zip 和便携版 exe 发布到 Releases。桌面版启动约 8 秒后在后台检查最新 Release，有新版弹窗提示（可「跳过这个版本」），也可在「设置 → 关于」手动检查。普通推送不会触发更新。更新只是下载新版程序，数据在 `推日数据` 文件夹，把它移到新版旁边即可。仓库公开后才能检查到更新。

开发时使用：

```sh
npm install
npm run dev -- --port 5173
```

开发地址：http://127.0.0.1:5173 。正式 PWA 安装和离线缓存使用生产构建（`start.cmd` 已自动完成）：

```sh
npm run build
npm run preview -- --port 4173
```

生产预览：http://127.0.0.1:4173 。Edge / Chrome 可通过浏览器菜单安装应用。本机回环地址支持 PWA；部署到其他设备访问的站点时使用 HTTPS，上传 `dist`；当前资源路径按站点根目录配置。新版离线缓存下载完成后自动激活，下次刷新使用新版；当前编辑页面不会强制重载，界面提供更新按钮。

浏览器按地址分别保存数据。`localhost`、`127.0.0.1` 及不同端口是不同工作空间；迁移时使用 JSON 导出/导入。

## AI 配置

在「设置 → AI 接口」填写 OpenAI-compatible 基础地址（例如 `https://api.openai.com/v1`）、模型名称与密钥。地址不包含 `/chat/completions`，应用会自动追加。浏览器会先直接请求该地址；很多中转站没有开启浏览器跨域（预检请求 OPTIONS 返回 403、响应没有 `Access-Control-Allow-Origin`），直连会被浏览器拦下。这时如果是通过 `start.cmd`／`推日.exe`／开发服务器打开的，应用会自动改由**本机服务转发**（见下方「AI 接口本机转发」）；纯静态部署没有本机服务，只能换用支持跨域的接口地址。

点击「从上游获取模型」使用当前地址和密钥请求 `GET /models`，筛选后可勾选多个常用模型，指定默认模型并保存。聊天窗口可切换已选模型，下一次请求使用新选择；请求执行或操作提案待确认期间禁用切换。切换结果会保存为当前默认模型，供下次聊天及推荐使用。手动填写的名称自动加入已选列表，上游不提供模型列表时仍可手动配置。模型列表兼容常见写法（`{data:[{id}]}`、`{models:[{name}]}`、顶层数组、字符串数组，会去掉 `models/` 前缀）。获取失败不会清空已选模型；列表中的模型未必支持聊天或工具调用，可逐个使用「检测工具调用」验证。模型列表请求不写入对话或备份，密钥仍按会话／记住本机选项保存。

点击「检测工具调用」选择工具模式或 JSON 提案兼容模式。推荐和自然语言助手共用此配置。工具模式与 JSON 兼容模式下，合法且明确的新建、编辑、Tag 覆盖和生日设置直接保存；完成后显示变更详情与「撤销」按钮。删除及角色身份、生日来源冲突仍需澄清或确认。

助手可选择默认／低／中／高思考强度，共用配置会发送到聊天和推荐请求。默认不额外发送参数，其他选项发送 `reasoning_effort`，需要上游及模型支持；不支持时切回默认。收起侧栏或进入设置不会取消正在运行的请求，助手入口旁显示运行转圈，重新打开可查看结果并撤销。只有点击「取消请求」才主动中断；关闭网页或刷新后使用已有续接功能恢复。

工具模式聊天使用 Chat Completions SSE 流式传输，回复逐步显示；工具参数跨分片组装，收到完整结束标记并校验后才执行，断流／截断不执行本轮工具。取消保留带中断标记的已接收文字，已保存操作仍可撤销。上游返回普通 JSON 时兼容整条回复；JSON 兼容模式先完整校验，再直接保存合法编辑，不显示原始提案片段。所有加载图标统一每圈 2 秒，系统要求减少动态效果时每圈 3 秒，仍保留加载状态提示。

上游在流中返回普通服务错误时，丢弃本轮半截工具参数，并自动使用非流式响应重试一次；仍使用相同工具与校验规则。鉴权、限流／额度及上下文过长有明确提示，不盲目重试。空白及 `&#x20;` 等空白实体不会形成「回复中断」消息。错误原文不显示，避免泄露上游敏感信息。

人物英文 Tag 填写到角色的 Tag（即默认预设的正向 Tag），别名仅保存实际名字。助手支持 `update_character_tags` 修改已有角色默认／指定预设，将误登记的别名原样移入 Tag 并移除误登记项，保留其他预设、真实别名和私人备注。编辑直接保存，完成后展示修改前后与撤销；无需重新创建角色。

助手现在可调用 `search_web` 直接搜索网页、`read_web` 读取正文，以及 `search_anilist` 查询备用角色资料。网页搜索默认 Bing，失败或结果不相关时尝试 DuckDuckGo。实际调用的进度、错误及可点击来源显示在「本次工具执行」中；不再以未执行的调用作为报告依据。搜索摘要仅是线索，网页生日通过 `propose_web_birthdays` 批量整理，必须引用本次成功读取的原文，明确且无冲突的日期直接事务保存，结果展示月日、来源和撤销；已有生日不同或来源冲突先澄清。没有明确公历月日或资料不可访问时保持待确认，不填猜测日期。助手可自动修改默认提醒、默认页面、节日／节气开关及日间／夜间／跟随系统主题，保留撤销。

网页检索由同源本地 Node 服务代为读取公开页面，解决浏览器跨域限制。双击 `start.cmd` 自动启动并升级此服务；`npm run dev` 和 `npm run preview` 也提供网页工具。仅上传 `dist` 的纯静态站点不包含该服务，会明确提示通过 `start.cmd` 启动；离线日历功能继续可用。网页禁止访问本机／内网，重定向也校验目标，最大 2 MB，搜索单个来源超时 12 秒、整体网页请求最长 30 秒。验证码、动态渲染页面、PDF 暂不支持，失败交给模型尝试其他来源。

**角色聊天**：寿星卡的「AI」按钮，以及「近期角色生日」卡片和角色库卡片上复制按钮旁的「AI」小按钮，都会打开和这个角色的聊天窗口：由 AI 扮演角色，口吻贴合原作。窗口顶部和每条回复旁都有角色头像，窗口比普通弹窗大；空对话里有随机显示的 5 条「快捷输入」（点一下就发送）：其中 40% 是绘画 prompt 相关，其余是普通聊天话题；AI 在为角色生成首页留言时会顺便写几句「玩家可能对角色说的话」存起来，优先用在这个角色的聊天里（没触发过留言生成的角色没有这些，只用预置的）。窗口里有「画点啥」按钮，点一下会从几种不同问法里随机挑一个（生日贺图、有故事感的场景、三种构图、服装配色背景、出人意料的画面等）发给模型，让它自由发挥，回复可一键复制。只发送角色名、作品、Tag 和人物特征，不含私人备注。对话按角色保存在本机浏览器里，重新打开窗口还在（最多 60 条，可点垃圾桶清空）。聊天增强（参考酒馆）：①**重新生成**最后一条回复，新版本加进去，用左右箭头在几个版本间切换；②每条消息可**编辑**（改完不会自动重发）、**删除**，悬停显示，触屏常驻；③**角色聊天设定**：在角色编辑器的「聊天设定」里填开场白（打开聊天时角色先说）、性格补充、示例对话，聊天时带给 AI；④**聊天中的我**：设置页「聊天中的我」填称呼和简介，AI 会用你的称呼叫你。窗口比普通弹窗大，但比之前窄一些、更高。聊天报错时，提示里会指向「设置 → AI 接口 → 连接诊断」。

**聊天里生图**：在「设置 → 生图接口」配置后，聊天窗口里的「拍张照」按钮会用预置提示词（Tag + 人物特征 + 随机挑的一种画面，输入框里有内容则按输入的来）出一张图，显示在聊天里；聊天里只显示一句场景话，发给接口的提示词不展示，图片下有「复制提示词」。**也可以在聊天中直接要求**，比如「给我拍张照」：系统提示会告诉模型，玩家想看照片时在回复末尾写 `[[拍照: 画面描述]]`，应用识别后按画面描述（加上角色 Tag 和人物特征）自动出图，标记本身不显示；这样不要求模型支持工具调用，任何对话模型都能用。设置里可选「提示词语法」（英文标签式／英文自然语言／中文自然语言），预置提示词和 AI 写的画面描述都按它来，另有固定的前缀和后缀；「图片比例」默认随机（3:4、4:3、1:1），也可固定、自定义尺寸或不传。各家生图接口并不统一，所以提供三种适配：①**OpenAI 图片接口**（`POST {地址}/images/generations`，最常见）；②**对话接口出图**（`/chat/completions`，模型在回复里给图）；③**自定义**（填完整请求地址和请求体模板，`{{prompt}}`、`{{model}}`、`{{size}}` 会被替换，认证头可选 `Authorization: Bearer` 或 `x-api-key`）。返回内容不要求固定格式，`url`、`b64_json`、data URI、Markdown 图片、`content` 数组里的 `image_url` 都能自动识别；识别不到时会显示返回的开头方便排查。同步返回图片的接口都能用，需要「提交任务再轮询」的异步接口暂不支持。生图接口没开浏览器跨域时同样走本机服务转发（自定义地址需要明确标记，仍只连公网地址）；设置页有「获取模型」和「测试生图」。AI 接口和生图接口都一样：地址和密钥填完整后稍等片刻会自动获取模型；点「获取模型」时，模型下拉先显示「正在获取模型…」和加载动画，拿到后直接展开供选择（也可以直接输入模型名）。含 base64 的图片只保留在当前窗口，不写入本机存储。

**连接诊断与上游错误**：设置页「AI 接口」里的「连接诊断」会用当前填写的地址、密钥和模型逐步检查，并写出每一步的结果：①浏览器直连 `GET /models`（被拦下通常是没有开启跨域）→ ②本机服务转发 `GET /models` → ③一次最小对话 `POST /chat/completions`，结果里不含密钥。接口返回错误时，提示里会带上上游给出的说明（截短、遮住密钥、忽略 HTML 错误页），例如 DeepSeek 余额不足的 402（单独提示「账户余额不足」）、参数被拒的 400／422，不再只显示一个状态码。

**AI 接口本机转发**：只在浏览器直连失败（`TypeError`，通常是没有跨域头）且有本机服务时才启用，路由是 `POST /__huiqi_ai/relay`。它刻意收得很窄：只接受同源页面发来的 JSON 请求（跨站和 `text/plain` 一律拒绝）；只转发 `GET …/models`、`POST …/chat/completions`、`POST …/images/generations`（自定义生图接口可带 `custom` 标记转发任意 POST 路径），不带查询参数；只转发 `Authorization` 或 `x-api-key`，不转发 Cookie 等其他头；只连公网地址（本机／内网的 AI 服务，如 Ollama，仍由浏览器直连）；经代理转发时域名由代理解析，直连时才在本机确认解析结果是公网地址；不跟随重定向，响应原样流式返回（支持流式对话），不保存也不记录密钥。同一主机转发成功一次后，本次打开期间后续请求直接走转发，不再白发一次会失败的直连。

网页服务自动识别 Windows 系统 HTTP(S) 代理；系统代理开关关闭时，如果已保存的回环代理地址仍在监听（如 Clash 的本机端口），仅本应用的网页工具使用该代理，不修改系统开关。每 5 秒重新检测配置，每次查询检测代理端口，无需手动配置环境变量或重启应用。聊天实际工具记录显示本次连接方式；`GET /__huiqi_web/status` 可查看不含密钥和代理认证信息的连接状态。PAC 和仅 SOCKS 地址暂不支持自动解析。

也支持 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 环境变量，显式配置优先于自动识别；例如在 PowerShell 中设 `$env:HTTPS_PROXY='http://127.0.0.1:7890'`（替换为实际端口）后启动。环境变量修改需要重启本地服务。查询失败会根据实际连接方式提示启动代理或检查现有代理节点，不重复堆叠提示。2026-10-10 已在本机通过自动检测到的代理实测 DuckDuckGo 返回洛琪希的相关网页，并成功读取生日资料正文；查到网页并不代表该角色存在官方公历生日，日期仍按证据与确认规则处理。

自然语言示例：

- 新增每年 11 月 11 日的自定义节日，提前 7 天提醒。
- 给香风智乃生日提前两周提醒。
- 把洛琪希的 Tag 改为 `Roxy migurdia, winter coat, scarf`。
- 查询我的角色，安排未来三个月的冬日主题任务。
- 直接搜索网页，核实生日待确认角色的具体日期，并整理带来源的修改提案。
- 把默认提醒改为提前 7 天，主题跟随系统。

AI 不发送角色、预设、事件与任务的私人备注，也不发送头像文件；会发送请求与最近对话、角色资料及必要的创作内容。密钥默认存在 sessionStorage，可选择存入本机 localStorage。备份不含密钥；浏览器保存密钥未加密，仅应在可信设备上使用。API 密钥只保存在浏览器的存储里（默认 sessionStorage，关闭浏览器即清除；勾选「记住密钥」才写入 localStorage），不在项目文件夹中，也不进入 JSON 备份。把整个文件夹复制到另一台电脑后，需要重新填写密钥和接口地址；角色、任务等数据同样存在浏览器的 IndexedDB 里，换电脑请用「导出 JSON／导入 JSON」迁移。

每次最多 8 轮调用、50 条修改；每批次事务提交。助手中可撤销，设置页也有操作记录。后续修改或新引用冲突时禁止覆盖式撤销。无配置、离线或模型失败时，本地功能仍可用。

模型等待响应头最多 120 秒；流式响应按连续 90 秒无数据判断中断，持续输出不会在 60 秒时被切断，单次响应最长 5 分钟。超时或流中断自动重试一次，不重复已成功执行的工具。长网页只向模型发送生日相关原文片段，完整原文留在本地用于校验引用。

网页资料、工具结果、已保存操作及待确认提案会保存在 IndexedDB。取消、超时或刷新后，可点击「继续本次操作」，也可先切换模型；相同网页和查询复用已有结果。达到 8 轮时暂停，手动继续允许下一组轮次，整次操作仍最多修改 50 条。「结束本次查询」只移除续接状态，已保存变更可撤销；清除对话同时清除续接状态。续接状态不含 API 配置或密钥、不进入备份。旧版失败的请求没有保存续接状态，升级后需要重新发送一次。

来源明确说生日保密／未公开时，助手可用 `record_birthday_findings` 保存来源、原文与核实结论，角色显示「生日未公开」，不猜测日期。纪念日不能填写为生日；新增纪念日需先向用户说明并确认。核实结论可撤销，并保留原有手动生日和来源。

## 与次元属性联动

[次元属性](https://befoer.github.io/acg-dna-web/)（属性图制作工具）和推日可以互相导入角色：

- 推日 → 次元属性：角色库点「导入次元属性」，把当前列表里的角色（名字、作品、头像）发过去，在次元属性里确认后加入新分类「推日角色」或所选分类。
- 次元属性 → 推日：先双击 `推日.exe` 启动推日，再在次元属性数据面板点「发到推日」选一个分类。通过 Bangumi 搜到图片的角色会带上 Bangumi 编号，导入后自动补全生日和资料；已有的同名或同一 Bangumi 角色会跳过。

数据由两个浏览器窗口直接传递（`postMessage`），双方只接受对方的固定地址，不经过任何服务器，接收方都会先弹出确认框。代码在 `src/acg-dna.ts`（发送）和 `src/acg-dna-receive.tsx`（接收）。

## 资料与日期

示例角色已关联对应 Bangumi 条目，其中 14 位提供已核对的生日资料快照（2026-10-10），启动时补齐本地空缺，断网也能显示；来源中标注核对日期。已有手动日期、来源和冲突候选不会被覆盖；洛琪希存在历法冲突，碧翠丝和珂朵莉缺少可用月日，仍需确认。其他角色可搜索并确认关联 Bangumi 条目，启动时联网补齐空缺生日；未获取到的资料每天重试，设置中也可点击「立即获取」，失败显示具体原因。伊莉雅使用《魔法少女伊莉雅》条目。Tag 始终保留原文。

首页「添加日程」与角色库「添加角色」打开同一个窗口，分「角色」（第一页，首页的「添加日程」默认打开它）和「自定义节日」两个分页：节日分页保存公历／农历节日；角色分页先在线搜索 Bangumi／AniList，点击结果后资料预览（头像、生日、作品、Tag）直接展开在该结果里，点「确认关联」（预览里和窗口底部各有一个，底部的不用滚动）即直接保存，不再打开编辑器；搜不到时点「手动添加角色」。手动新建的角色保存后，也会自动打开资料搜索。编辑器提供「获取头像和生日」，用当前角色名搜索；选择正确候选、确认关联，再保存角色。设置中的「立即获取」搜索未关联角色，读取完整姓名、别名和作品信息；身份匹配且唯一的候选直接关联并保存头像、生日，无需再手动确认。重名、作品不匹配或候选资料读取失败时保留手动选择入口，不取第一个结果。未关联角色默认折叠，标题显示数量，展开后可查看候选状态。已有手动图片、生日、Tag 和备注保留；来源冲突的生日仍待核实。自动关联记入操作日志，可撤销。AI 新增的未关联角色也适用。

本机浏览器直连 Bangumi／AniList 超时或网络失败时，自动尝试同源本地资料服务，使用网页工具同样的代理检测；两条路径都失败才显示网络弹窗。头像直连失败时，Bangumi／AniList 图片也可由本地服务获取，并由 PWA 缓存用于离线查看。角色资料路由只接受固定公开角色资料接口和图片来源，不带任何密钥，不接受任意 URL 或写入接口（AI 接口的转发是另一条独立的、更窄的路由，见上文「AI 接口本机转发」）。纯静态部署没有本地服务，需使用能直接访问这些来源的网络。

**自动获取 Tag**：选中角色后，用英文名（其次日文名、中文名）先查 Danbooru 的角色标签（`tags.json`，人物特征来自 `related_tag.json`），Danbooru 不可用或没有结果时回退 AnimaDex（`animadex.net/api/characters/search`，数据同样来自 Danbooru，直接带外观标签）。**Tag 只保存角色标签本身**，写成提示词格式（下划线变空格、括号加反斜杠转义，如 `nahida \(genshin impact\)`）；发色、瞳色、服装等**人物特征**（如 `loli, pointy ears, green eyes, white hair`）另存在角色的「人物特征」里，不随复制按钮复制，可用「同时保存人物特征」开关控制。有多个候选时可切换，两个字段都能手动改写；两个来源都失败时只提示原因，仍可手动填写。这两个来源都没有跨域头，需要通过 `start.cmd`／开发服务器的本机资料服务代理（只接受固定的只读查询，不接受任意地址）；仅上传 `dist` 的纯静态站点没有该服务，只能手动填写。Danbooru 对部分网络启用了 Cloudflare 人机校验，被拦时（403）自动使用 AnimaDex。查询时先按开头匹配（`paimon*`，走索引，很快），没有结果再放宽到包含（`*paimon*`）；网络层瞬断会自动重试，本机服务连不上 Danbooru 时浏览器还会自己直连一次（Danbooru 带跨域头；系统用 PAC 脚本代理时 Node 侧可能走不通而浏览器走得通）。读取 Windows 系统代理的 PowerShell 命令在机器繁忙时可能超时，现在超时后沿用上一次读到的设置并很快重试，不会因为一次读取失败就当成没有代理而直连（直连在 fake-ip／TUN 等环境下会被拦下）。仍然失败时，错误信息里会带上底层错误码（如 `ECONNRESET`、`ETIMEDOUT`）和本机服务、浏览器直连两边的原因，便于判断是代理、证书还是站点的问题。

**单一 Tag 与复制**：角色不再有多个 Tag 预设、反向 Tag 和「组合 Prompt」窗口，只保留一个 Tag（沿用原默认预设的正向 Tag 保存，旧数据与 JSON 备份兼容，旧的多余预设和反向 Tag 原样保留但不再显示）。日历、首页、角色库、年度选题和命令面板里的复制按钮都直接复制该 Tag，并弹出「已复制」提示；角色库的按钮是带文字的「复制 Tag」。任务只有一个 Tag 字段。人物特征保存在角色的 `traits` 字段，仅用于查看和备份。

**标星**：角色可标星（角色库和首页卡片右上角的星标、编辑器里的「标星」）。角色库、首页近期生日、日历、创作任务和年度选题都有「仅标星」筛选，角色库还可按「标星优先」排序。标星和头像本地化不写入操作记录，但会同步修正记录快照，不影响之前操作的撤销。IndexedDB v6 为角色增加 `starred`、v7 增加 `traits`（旧数据默认未标星、特征为空）。

**头像保存到本机**：远程头像（Bangumi／AniList）会在后台下载、缩小到 480 px 宽并以 WebP 保存进 IndexedDB，之后离线、换网络或来源下线都能显示，并随 JSON 备份导出（17 位示例角色约 0.8 MB）。优先走本机资料服务，失败再尝试浏览器直连；单张失败不影响其他，联网后自动重试。设置页「头像保存到本机」显示进度，可手动「立即保存」。

**头像显示位置**：角色编辑器里，鼠标移到头像图片上时右上角会出现「调整图片位置」按钮；点开后直接在图片上拖动（上下左右都行，也支持方向键），底部的「缩放」滑块可以先放大再移动，用来裁掉少数图片顶部过大的空白。拖动时图片不会被浏览器选中变蓝，「拖动图片以调整位置」的提示一直显示；图片上方的「保存位置」确认、「取消」放弃，调整中直接点「保存角色」也会一并保存；触屏设备上按钮常驻显示。位置保存在角色的 `avatarX`／`avatarY`／`avatarZoom`（IndexedDB v8，旧数据为默认值），角色库、首页、日历、列表等所有头像都按它显示。

外观默认跟随系统的日间／夜间模式，可在设置中固定选择。月历点击任意日期，在右侧「当日安排」面板查看当天事项、编辑角色生日或日程、添加日程及创作任务（新建事项默认填入所选日期），其下「本月概览」汇总当月生日与节日。

界面为「薰衣草雾」配色：偏冷的薰衣草灰白（夜间为深靛灰）打底，靛紫负责按钮、选中与链接，亮粉色（取自 ui-ux-pro-max 配色库的 #F472B6 / #BE185D 一组）只用来标记生日与倒计时，渐变只出现在极浅的底色里；Logo 是低对比的薰衣草到雾蓝渐变。左侧是图标侧轨（手机为底部导航），顶部有全局搜索（Ctrl / ⌘ + K 快速跳转页面、搜索角色、复制角色 Tag、执行快捷操作）、「新建」菜单与 AI 助手入口，日间／夜间切换是顶栏右侧的单个按钮。工作台首屏为今日日历、下一位寿星与数据条（关注角色、近期生日、待完成创作、进行中的创作），标题位置是看板娘式的旁白，不带日期，例如「今天是灰之魔女（伊蕾娜）的生日。／明天是重阳节，15 天后轮到露露卡。」（今天没人过生日时不特意说「没有」，直接从下一位寿星说起，如「15 天后是露露卡的生日。」；同日多位用「、」连起来）；寿星卡是一块窄窄的玻璃矩形，大尺寸的图片卡压在它左缘上，里面是角色口吻的生日留言（无边框，下方三个纯图标按钮——「AI」（和这个角色聊天）、「建任务」、「复制 Tag」——与留言框同宽）。**留言是预先生成并存在本机的**：配置了 AI 接口后，应用打开、空闲时会为最近要过生日的两位角色各让 AI 一次写 5 条（当天的和提前的分开存，留言里不写具体天数，所以过几天仍然适用），打开首页时直接取一条没看过的显示，不用等 AI，每次打开页面都不一样（留言上没有刷新按钮，换留言就是重新打开页面）；没看过的少于 2 条时再悄悄补一批。只有第一次（还没存过）或存的用完时才会现场请求。留言只发送角色名、作品名和少量已有留言（避免重复），设置里「首页寿星卡自动生成角色留言」可关闭，关闭后不会在后台调用 AI，只在点「收取留言」时才请求；其下「近期角色生日」是整行铺满页面的大头像卡片（图片与卡片边框齐平；生日日期和「N 天后」并成一颗胶囊放在左上角，视线不用在图片两端来回跳），最后一格固定为「全年生日」，右上角的 1／2／3 行可切换显示行数，「仅标星」只看标星角色（行数偏好保存在本机浏览器）；再下方是创作队列、灵感（左）与节日节气（右）。创作任务是可拖拽换列的四列看板（可切换为列表）。角色库卡片左上角统一显示距离生日的天数，星标小而淡（右上角），可按作品筛选，并用自绘的排序菜单选择生日临近（默认）／添加顺序（最新在前）／标星优先／名称。「生日临近」按距离下一次生日的天数从小到大，没有已确认生日的排最后；「添加顺序」是角色加入工作空间先后的倒序：先按创建时间，同一批内置角色按编号，最后按名称，最新添加的排在最前（弹出层完全跟随主题；其他下拉框的选项列表也已适配深色）；设置页左侧有分区导航。日历月视图里，有生日的日期格子直接用角色头像铺满整格，名字压在图片上（多位同日生日并排分栏，其他事项显示在图片下方的小标签里），手机上只显示头像。

工作台「节日与节气」可按公历、农历、节气、自定义筛选，按日期显示接下来的 5 个不同节日；排除一项后会用后续节日补齐，检索未来两年，与近期生日的行数设置独立。每行「−」排除此节日（年度重复节日各年均生效），同时从今日安排、日历和本地节日推荐中移除；顶部「显示排除」默认关闭，开启后可查看并用「+」恢复。排除记录保存在本机设置及 JSON 备份中。

不提供题材／节日 Tag 编辑或自动拼接。年度选题保留中文主题、理由、日期与关联角色；AI 推荐无需生成英文题材 Tag。复制及由选题创建任务只使用角色的 Tag。旧备份中的题材字段兼容保留，不再用于节日日历导出；已有任务 Tag 不受影响。

角色编辑中可勾选「无生日」，清空月日并显示「无生日」，不计入生日待确认，不再自动补齐生日；仍可关联资料、获取头像并参与季节选题。取消勾选可恢复待确认并填写日期。助手可按明确请求使用 `noBirthday` 修改此状态。IndexedDB v5 增加节日排除设置，v6 增加角色标星，v7 增加人物特征，升级保留已有角色与 Tag。

AniList 为备用资料源：公开 GraphQL 接口提供角色 `dateOfBirth`、头像和作品，不需要密钥。名称搜索先读取 Bangumi 的英文名／罗马字别名，再将英文关键词提交 AniList；自动生日获取、导入窗口和 AI 搜索共用此流程。已有 Bangumi 响应会复用，不重复读取。优先采用标注为英文名的字段，保留单词次序，不从人物 Tag 猜名字。Bangumi 暂不可用时可使用已有英文别名或内置英文名称；始终无法取得英文名时提示补充，避免直接发送中文搜索。AniList ID 和链接无需姓名转换。Bangumi 请求失败或缺少生日时尝试 AniList；未关联 AniList ID 时要求名称匹配、已知作品一致且候选唯一，否则不自动导入。已有来源冲突仍待确认，不会用备用资料掩盖冲突。导入窗口可手动选择 AniList，搜索英文名称、ID 或链接，预览后确认。不能保证所有角色都公布生日。

浏览器直连最多等待 12 秒，本地资料服务连接最多等待 15 秒；两条路径均失败时显示弹窗，提示检查网络及打开 VPN／代理，提供重试按钮。设置中有「补齐本地生日」按钮、持续获取结果、应用版本和更新检查。已保存资料不依赖外部接口。

默认时区 Asia/Shanghai，提前 14 天提醒。农历节日按非闰月每年计算，不包含法定调休。农历某年没有指定日（如小月三十）时该年不生成事件。闰日生日平年按 2 月 28 日显示。

ICS：普通公历生日/节日按年度重复；农历、节气和闰日生日导出具体日期。全量导出范围未来两年；日历页面导出当前范围或选中事项。关闭应用后的提醒由导入的日历软件执行，其是否支持 VALARM 取决于客户端。

数据在 IndexedDB 中，不自动云同步。清除站点数据会删除工作空间，定期在设置中导出 JSON。导入为确认后合并：同 ID 更新，其他记录保留，更新默认提醒和视图；角色引用与版本会校验。API 密钥不受导入影响。

## 结构与扩展

- `src/external-network.ts`：网络超时、错误类型及提示。

- `src/ai-stream.ts`：SSE 解析、文本增量和工具参数组装。

- `src/App.tsx`：应用外壳、编辑器弹窗、设置页与 AI 助手面板。
- `src/shell.tsx`：侧轨、顶栏、新建菜单与命令面板。
- `src/ui.tsx`：共享组件（头像、弹窗、空状态等）、导航与文案常量、日期小工具。
- `src/select-menu.tsx`：自绘下拉菜单（键盘可操作，跟随主题）。

- `src/character-sort.ts`：角色库排序。
- `src/pages/`：工作台、日历、角色库、年度选题、任务看板各页面。
- `src/styles/`：设计令牌（`tokens.css`，日间/夜间换肤入口）与分层样式。
